Wilderness Terrain Painter

❓ Help — what everything does (click to expand)

Loads all 25 wilderness screens onto one continuous canvas, laid out exactly like the real 5x5 world, so terrain painted across a screen boundary is connected by construction. The "Map" dropdown switches to the dragon dungeon or a mini-dungeon variant instead — each is a standalone map with its own palette, painted the same way. Pick a brush, click or click-drag to paint. Export copies a map's LEGEND/ROWS to the clipboard, ready to paste over its existing declaration in its file (wilderness screens live under js/maps/wilderness/; the dungeon and mini-dungeons live under js/maps/). "Place Dungeon Entrance" marks the one fixed spot every save's dungeon spawns at (only meaningful on the wilderness map) — "Copy position" copies the exact value to paste into DEFAULT_DUNGEON_ENTRANCE_POSITION in js/state.js. "Check Map" flood-fills from the town entrance in stages, matching the intended axe → pick → canoe (boat) → portal → dragon progression: it only unlocks thicket/mountain/water terrain after confirming that stage's own tool dungeon is actually reachable with whatever's already unlocked, so a chicken-and-egg gate (like the pick dungeon sitting behind thicket while the axe dungeon itself is unreachable) gets caught. Yellow tint = only reachable with some tool, red = not reachable even with every tool, magenta = exactly where the first broken stage gets stuck. Once the tool-gated chain checks out, every placed superboss marker is also checked against "reachable with every tool" (they don't gate further progression, so they aren't part of the staged order above - just verified reachable once you're fully tooled up). Dungeon-interior maps don't have their own reachability check yet. "Place Tool Dungeon Entrance" works the same way for whichever tool dungeon is selected in the dropdown next to it — copies paste into that entry's screenId/x/y in js/data/toolDungeons.js. "Place Super-Boss Marker" is the same idea again for whichever superboss id is selected in its dropdown (populated from SUPER_BOSSES' keys in js/data/superBosses.js) — the "Has own dungeon" checkbox is saved onto the marker alongside its position (hasDungeon: true for a superboss fought behind its own dungeon entrance, false for one fought on the spot in the open wilderness). "Export All Changed to Files" writes every changed wilderness screen (plus the superboss marker positions) straight to disk in one click, instead of copy/pasting each screen by hand — if node tools/terrain-painter/server.js is running, it uses that automatically; otherwise it falls back to "Choose Repo Folder" + the File System Access API (Chrome/Edge only). "New Dungeon" starts a brand-new, blank dungeon interior from scratch (for a superboss's own dungeon) instead of loading an existing map file — prompts for a map id and a width/height, then switches into the same painting view used for every other dungeon, filled with cave floor tiles ready to paint over. Its palette is caveFloor/caveWall/exit/guardian — one exit tile (where the player starts) and at least one guardian tile (the fight itself, via guardianBattle — not boss, which is wired specifically to the one real dragon fight) are required before "Save New Dungeon to Server" will write it to js/maps/superBosses/ and register it in js/main.js — it also asks for the guardian's monster id (a key from MONSTERS in js/data/monsters.js) and needs the Node server running (no File System Access fallback, since there's no existing file to patch). The "Hook up to superboss" dropdown next to that button is optional but recommended: pick the superboss this dungeon belongs to and saving will also set that entry's dungeonMapId and hasDungeon: true in js/data/superBosses.js automatically - leaving it on "(none)" saves the dungeon file itself but leaves that link for you to add by hand, same as every dungeon before this dropdown existed.
